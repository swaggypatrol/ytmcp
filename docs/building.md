Dependencies are locked in `Cargo.lock` and `pnpm-lock.yaml`. Install the workspace with:

```sh
pnpm install --frozen-lockfile
```

## Recipes

Run `just --list` for the full list.

| Recipe | What it does |
| --- | --- |
| `just doctor` | Prints toolchain, session (Wayland, KDE), GPU, audio and secret-service details and lockfile hashes. |
| `just types-check` | `cargo check` for all crates and type checks for the protocol, bridge, desktop and UI packages. |
| `just lint` | `cargo fmt --check`, `cargo clippy -D warnings` and the TypeScript type checks. |
| `just test` | Rust workspace tests, pnpm workspace tests, process tests against a freshly built debug daemon, desktop shell tests and UI transport end-to-end tests. All offline, with the committed `Cargo.lock`. |
| `just test-control` | Builds the daemon and the MCP adapter and runs the MCP stdio smoke test against one synthetic daemon. |
| `just bridge-check` | The bridge's offline DOM and fixture tests. |
| `just gen-protocol`, `just gen-control` | Regenerate the JSON Schemas and TypeScript types from `crates/protocol` and `crates/control-api`. Generated files are committed; never edit them by hand. |
| `just dev-mock` | Builds the UI and desktop shell and starts them with synthetic data (`YTM_GLASS_MODE=mock`). No account and no network. |
| `just dev` | Builds a debug daemon and starts the app against the official web player. |
| `just build-release` | Release builds of the daemon, MCP adapter, bridge, UI and desktop shell. |
| `just package` | Builds the Arch package; see below. |
| `just test-live` | Catalog live tests; refuses to run without `YTM_GLASS_ALLOW_LIVE=1` and needs a signed-in session. |

The offline gates are `just lint`, `just test` and `just test-control`. They need no account, no network access to YouTube and no audio device. Heavy builds can be pinned to a CPU set with `taskset -c <cpus> just ...`.

## Packaging

The Arch package is built from a committed tree:

```sh
git status --porcelain    # must be empty
just package
```

`just package` runs `tools/package/build-package.sh`, which refuses a dirty working tree, copies [packaging/PKGBUILD](../packaging/PKGBUILD) into a fresh temporary directory and runs `makepkg --cleanbuild --force` with the full `HEAD` commit as a local git source. The package lands in `packaging/out/` (override with `YTM_GLASS_PKG_OUT`). The first build fetches the locked Cargo and pnpm dependencies and the Electron zip (checksum-pinned in the PKGBUILD); an Electron zip in the local Electron download cache is reused when its checksum matches. Rust builds use `--frozen` and pnpm uses `--frozen-lockfile`. The `check()` step runs the Rust and pnpm workspace tests. No root access is needed to build.

Reserve at least 12 GiB for the build directory; point `TMPDIR` elsewhere if `/tmp` is small. The PKGBUILD checks that the Rust, Node.js and pnpm in `PATH` are the pinned versions. A standard clean chroot ships different versions, so preinstall the pinned ones for the build user if you build in one.

Runtime dependencies, optional dependencies (`kwallet`, CJK fonts, `pipewire-pulse`) and build dependencies are listed in the PKGBUILD. The package installs:

- `/opt/ytm-glass/`: Electron with the app, UI, bridge and the `ytm-daemon` binary under `resources/`; `/usr/bin/ytm-glass` (the launcher) and `/usr/bin/ytm-glass-mcp` are the entry points.
- `/usr/share/doc/ytm-glass/BUILD-MANIFEST.txt`: the source commit, toolchain versions, the embedded Electron component versions, lockfile hashes, and the versions and licenses of the build machine's direct system dependencies.
- `/usr/share/licenses/ytm-glass/`: the MIT license, Electron and Chromium notices, and per-crate and per-package notices generated by `tools/package/gen-notices.mjs`.

Inspect a package with:

```sh
pkg=packaging/out/ytm-glass-*.pkg.tar.zst
pacman -Qip $pkg
bsdtar -xOf $pkg usr/share/doc/ytm-glass/BUILD-MANIFEST.txt
```

Install with `sudo pacman -U` and remove with `sudo pacman -R ytm-glass`; removal keeps the profile, settings and cache. Upgrading migrates the database and backs it up first; a package older than the database's schema cannot open it.

## Live checks

Live checks run against the real official page and are never part of the offline gates. The MCP live scripts in `tools/mcp/` take an extracted package, so they test exactly what would be installed:

```sh
mkdir -p /tmp/ytm-pkg /tmp/ytm-evidence
bsdtar -xf packaging/out/ytm-glass-*.pkg.tar.zst -C /tmp/ytm-pkg
python3 tools/mcp/with-null-sink.py python3 tools/mcp/live-read.py \
  --package-root /tmp/ytm-pkg --evidence-dir /tmp/ytm-evidence
```

- **Null sink.** `tools/mcp/with-null-sink.py` loads a temporary PulseAudio/PipeWire null sink, starts the command with `PULSE_SINK` pointing at it, moves any player stream that still lands elsewhere onto it, and unloads it afterwards. Use it for every live check so nothing plays out loud.
- **Signed-in profile.** The scripts start the extracted player with your existing profile and refuse to run while another instance owns that profile or the control socket. `live-read.py` (read-only tools and cursors), `live-collection.py` (album playback), `live-queue.py` (queue writes, interruptions and removals), `live-dj.py` (track-ending prompts and check-ins through a real MCP client) need a profile that is signed in. They play public music and change only the queue.
- **Agent runs.** `live-agent-dj.py PACKAGE_ROOT EVIDENCE_DIR` and `live-agent-loop.py PACKAGE_ROOT EVIDENCE_DIR [MINUTES]` drive Claude Code in headless mode (`claude -p`) as the DJ client, and need the `claude` CLI.
- **Account writes.** `live-writes.py` changes the signed-in account. It only appends to and removes from a private playlist named `YTM Glass Test`, and likes a public track that it first confirms is neutral, then restores it. Run it only against an account where that is acceptable.
- **Desktop QA.** `tools/qa/` holds the installed-app gates (`m0.mjs`, `g6-installed.sh`, `perf.mjs` and others). They need `YTM_GLASS_ALLOW_LIVE=1`, a KDE Plasma Wayland session and a signed-in profile, and some of them lock the screen or open windows.

Evidence files are redacted before they are written: titles, account identifiers and anything that looks like a cookie are removed or hashed.

## Versioning

The application version (`1.0.0`) is kept in `config/app-identity.json`, `package.json` and the Cargo manifests; the Arch package revision (`pkgrel`) in `packaging/PKGBUILD` counts builds of that version, so releases are named `1.0.0-N`. [CHANGELOG.md](../CHANGELOG.md) has one section per release. When updating Electron, Rust or pnpm, update the pinned version and checksum, regenerate the license notices, run the offline gates, then rerun the affected live checks with a new package. When the official page changes, add a minimal scrubbed fixture under `bridge/` and cover ready, lifecycle, control observation, queue and failure behavior; catalog shape changes are covered in `crates/ytm-data/`.

## Data, logs and troubleshooting

| Item | Location |
| --- | --- |
| Official page session | `$XDG_DATA_HOME/ytm-glass/electron-profile/` |
| Settings, MCP registrations | `$XDG_CONFIG_HOME/ytm-glass/` |
| Database | `$XDG_DATA_HOME/ytm-glass/ytm-glass.db` |
| Cover cache | `$XDG_CACHE_HOME/ytm-glass/covers/`; "Clear cache" in Settings keeps the sign-in |
| Logs | stderr when started from a terminal; otherwise `journalctl --user -b`, searching for `desktop-host` or `ytm-daemon` |

| Symptom | What to check |
| --- | --- |
| The main window does not start | `startup_failed` in stderr; that `/opt/ytm-glass/resources/bin/ytm-daemon` exists; `pacman -Qkk ytm-glass`. |
| The player page disconnected | Reopen it from the banner and wait for the handshake. Commands that were in flight settle by reading the state back. |
| Signed out or account mismatch | Sign in again on the official page. Account writes stay disabled until the player and library accounts match. |
| Media keys do nothing | `busctl --user list` should show `org.mpris.MediaPlayer2.ytm_glass`, and the bridge should be connected. |
| Browsing fails but playback works | Check the catalog error code, network state and cache flags in the diagnostics view. |
| An MCP client cannot connect | The player must have been restarted after the first registration; the registration must not have expired; the client must use the printed credential path. |

When reporting a problem, include the package version, Plasma/KWin, kernel and GPU driver versions, display scaling and redacted logs. Leave out credentials, raw site responses, media URLs, private library contents and sign-in screens.

## Public export

`tools/release/export-public.sh` builds the public source tree from the committed `HEAD`:

```sh
tools/release/export-public.sh /path/to/empty-directory
```

It refuses a target that exists and is not empty. It copies an explicit allowlist of tracked paths (sources, tests, fixtures, packaging inputs, `docs/`, `README.md`, `CHANGELOG.md`, `LICENSE`), and never `internal/`, local agent instruction files, `packaging/out/`, `node_modules/` or `target/`. It then scans the exported tree and fails, listing every hit, if it finds:

- CJK characters outside the files that legitimately contain Chinese (the zh-CN UI translation, Chinese parsing rules and their tests, the desktop entry's localized name);
- sensitive patterns: home directory paths, e-mail addresses other than `noreply` placeholders, and the owner-specific names, handles and hostnames listed in a local, unpublished pattern file (`internal/release/sensitive-patterns.txt`, required);
- broken relative links in the exported Markdown files (`tools/release/check-links.py`).

Only when the scan is clean does it run `git init` in the target and make one commit, "Initial public release". The commit is authored as `PUBLIC_AUTHOR` (`Name <email>`), by default `YTM Glass <noreply@ytm-glass.invalid>`; the local git identity is never used.
